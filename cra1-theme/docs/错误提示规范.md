# 主题错误提示规范

适用于官网、会员中心、购物车、独立主题后台和安装更新页面。新增页面、模块适配和接口必须遵循同一规则。

## 前台访客提示

提示使用普通访客能理解的中文，说明当前影响及下一步操作。保留余额不足、库存不足、验证码错误、必填信息缺失等有效业务原因。

不得向访客返回系统异常、服务器目录、SQL、堆栈、供应商地址、认证资料或完整请求。失败响应中的嵌套字段也必须清理，不能只替换弹出的提示文字。错误编号可以保留，便于客服查找。

| 情况 | 提示示例 |
| --- | --- |
| 网络断开，读取失败 | 网络连接暂时中断，请检查网络后重试 |
| 登录过期 | 登录已失效，请重新登录 |
| 商品配置加载失败 | 商品配置暂时无法打开，请重新加载；仍无法打开时请联系客服 |
| 报价失败 | 暂时无法获取价格，请重新报价；确认金额后再提交 |
| 提交续费后响应丢失 | 尚未确认续费是否提交成功，请先到订单列表查看，避免重复提交 |
| 下单后响应丢失 | 尚未确认订单是否创建成功，请先到订单列表查看，避免重复下单 |
| 付款状态无法确认 | 尚未确认付款结果，请先查看订单状态，避免重复付款 |
| 无权查看或订单不存在 | 订单不存在或你无权查看，请到订单列表确认 |

没有收到响应不等于服务端没有执行。写入请求超时、断线、网关错误或响应无法解析时，不得提示“操作未执行”，不得自动重试下单或付款。订单已创建但收银台无法打开时，应继续已有订单。

## 后台与安装更新提示

已认证管理员的提示包含失败操作、可证实的原因、受影响位置和处理建议。路径优先使用网站根目录下的相对路径。安装页同样使用相对路径，隐藏服务器私有目录结构。登录、找回密码等未认证接口不展示内部诊断。

文件操作应指出具体位置、实际 PHP 运行账号、检测到的属主/组和权限。使用有效进程身份，不能用脚本文件属主代替运行账号。无法检测时直接说明无法确认。

例如：`创建临时文件失败：runtime/cra1_theme/config.json。权限不足。检查位置：runtime/cra1_theme；PHP 运行账号：www；当前属主/组：root:root；权限：0755。请调整该目录的属主，使网站账号有读取、写入和进入权限。`

权限建议必须符合实际用途。目录属主正确时，公开资源目录通常可用 755，私密目录用 700、私密文件用 600；共享组写入需要单独配置。root 属主的 755 目录不会因此允许 www 写入。不得建议整站 777，也不能自动放宽安全库、密钥权限。

只根据真实失败信息分类：权限不足、只读磁盘、配额用完、磁盘空间或 inode 用完、open_basedir 限制、文件锁、写入不完整、替换失败。不能把所有文件错误都解释为“目录不可写”。数据库连接、认证、授权、结构缺失与查询兼容问题也应分别解释，不返回密码、原始 SQL 或连接地址。

无法确认原因时，提示失败步骤和参考编号，请管理员检查记录；不得编造原因。原始英文异常不直接展示为操作说明。

## 保存结果

| 状态 | 处理规则 |
| --- | --- |
| 明确未保存 | 说明校验、权限或写入失败的具体原因；仅在已验证的原子写入或回退链路中说明原配置保留 |
| 已保存但同步失败 | 保留成功状态，说明配置已保存，以及快照、SEO 文件或审计中失败的部分及原因，提供对应修复入口 |
| 结果未确认 | 提醒先核对服务端状态，避免重复提交；保留编辑内容，不声称保存成功、保存失败或已经回滚 |
| 配置版本冲突 | 保留 409 及现有差异合并流程，不能强行覆盖他人修改 |

接口继续使用 `{status, msg, data}`，保留稳定错误码和请求编号。主配置提交后的辅助失败不能被改写成“未保存”。字段 `save_state` 可标明 `saved`、`partial`、`unknown`；同步状态继续沿用 `snapshot_ok`、`seo_ok`、`audit_ok`。

## 实现与验证

前台共用 `CRA1Shared.Errors.message/payload`，服务端使用 `Http/CustomerError` 清理失败响应。后台使用 `Failure` 捕获真实文件操作失败，由 `Diagnostics` 解释和脱敏；安装器沿用自己的阶段与恢复结果。

成功的业务数据与支付插件 HTML 不做错误内容清洗。安全验证的布尔标志、可选验证方式及原生回调契约必须保留。测试需要覆盖嵌套泄露、有效业务原因、写入超时、实际运行账号权限、部分成功和恢复结果，失败测试使用隔离数据。

较长提示允许换行及断词，不能撑破卡片或手机页面。提示正文不重复展示相同说明，详细信息按需放在错误详情中。
