# 唯一发行源码与构建

正式入口为 `cra1-theme/scripts/build.mjs`。会员源码位于 `cra1-theme/source/member`，后台源码位于 `cra1-theme/source/admin`，共用层位于 `public/cra1-shared/src`，官网源码位于 `public/web/cra1/src`。旧的站点外部构建工程退出发行流程，不作为构建依赖。

构建需要 Node 22、Python 3 与 PHP 7.4（资源生成与测试），客户安装不需要这些构建工具。

```bash
npm ci --ignore-scripts --prefix cra1-theme/source/member
npm ci --ignore-scripts --prefix cra1-theme/source/admin
npm ci --ignore-scripts --prefix public/cra1-shared
npm ci --ignore-scripts --prefix public/web/cra1/src
CRA1_RELEASE_STAGE=/非站点目录/新暂存目录 CRA1_RELEASE_ID=新的资源标识 node cra1-theme/scripts/build.mjs
python3 cra1-theme/scripts/inventory.py
python3 cra1-theme/scripts/package.py --stage /非站点目录/新暂存目录 --out /非站点目录/新候选包目录
```

输出必须是站点外的新目录。直接运行子工程构建会被拒绝；不会默认覆盖线上资源。资源标识是不可变目录标识，不等于对外版本号。对外版本号由 `cra1-theme/release.json` 的 `version` 字段维护，当前为 `v17.1`，渠道 `test`；构建、安装合集、主题后台和 GitHub Release 使用同一版本号，旧包没有该字段时继续读取原发行标识。

安装包、更新包和源码包作为内部候选文件分别生成。`package.py` 同时在输出目录的 `delivery/` 下生成唯一的客户安装交付文件：`CRA1-theme-{版本号}-install-with-guide.zip`。其中包含原始安装 ZIP、PDF／HTML／Markdown 图文教程、教程图片、目录保护示例和安装说明；QQ 群信息保留。版本号以安装包内部发行清单为准，不从文件名猜测，也不自行升级版本。

已有安装包只需重新组合教程时，运行以下命令；不会重编译或修改安装包内容：

```bash
python3 cra1-theme/scripts/bundle_install.py --install /站外目录/已验证安装包.zip --out /站外目录/新交付目录
```

图文教程统一从仓库 `docs/installation.md`、`docs/installation.html`、`docs/installation.pdf` 及 Markdown 引用的已脱敏图片读取；这些输入也进入源码包，保证重打包不依赖开发机器上的教程副本。客户下载页只提供合并后的安装交付 ZIP，不再单独上传旧安装包或旧教程附件。

运行包不含 Node 依赖、测试、站点配置、数据库、日志、密钥和账号。原生基础组件由清单登记后从客户合法安装中复用，归属和版本都可查；不将 default 文件夹打进主题包。

`source/legacy-assets` 是已登记的样式兼容输入，用于保留现有页面的视觉兼容。其他旧构建入口不参与发行。统一私有清单与生效指针选择官网、会员、购物车、共用层及后台资源，保留旧地址用于现有站点回退。

复现构建时使用同一源码、锁文件、Node/PHP 版本和资源标识；先比较所有输出及候选包校验值。未经来源核验的素材、原生依赖或未验证系统组合不得通过正式发行门禁。

`source/native-references.json` 是固定的构建输入，登记依赖、文件归属、观测校验值及已核实官方校验值。不会按构建机器是否恰好存在 default 文件来决定负载。验证源码包须在全新临时目录独立执行四次 `npm ci`，再通过 `tests/source-rebuild.py` 比较全部构建文件及三个重打包校验值。

私有后端按资源标识放入 `backend/releases/`，请求开始时固定选定实现，资源全部准备后才提交统一指针。回退保留较新的安全后端，避免旧页面撤回数据净化和安全验证。后台中断恢复不依赖前台资源或媒体库初始化，重新登录后可恢复。

`docs/asset-rights.json` 按文件及 SHA-256 登记来源、许可和证据。只有绑定实际字节且三项依据齐全的记录才生成已核验标记；未登记素材继续阻断发行。商家上传媒体和导入图标不进入包中。依赖声明不能自动替代图片、字体、商标及图标的权利依据。

测试发行另设 `CRA1_RELEASE_CHANNEL=test`，默认仍为候选渠道。测试包绑定官方基线、业务与公开 HTTPS 生命周期记录；使用 `scripts/release_gate.py --channel test` 检查。素材及完整商业支持组合不作为测试发行门禁，但保留原记录。测试渠道不跳过文件完整性、隐私、原生契约、路径边界、更新事务或安全检查，默认商业门禁仍保留。复现测试包时必须使用相同渠道、源码与发行标识。后续升级方式见《测试版与后续更新》。

图标溯源可使用 `scripts/icon-rights.py --upstream-dir /已固定的上游资料 --out /新的站外证据目录` 复核。该脚本不联网、不改图标和登记表：验证 npm 包完整性、许可原文校验值及每个图形的数据，随后验证净化派生文件。它允许记录中的容器尺寸、绘制顺序和单色转换等修改，不能用近似图形批准来源不明的文件。已登记文件的来源、原作者与许可见 `licenses/icons/ATTRIBUTION.md`；尚未匹配或来源未确认的图片及图标仍计入完整商业发行门禁。测试渠道可在技术门禁通过后进行功能验收，但不会将这些记录改为已获授权。
